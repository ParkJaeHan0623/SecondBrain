## 📄 적용일자 비교 쿼리

```sql
SELECT NBW_MESG_VER_NO, NBW_MESG_APLY_DT
  FROM CPBBO_MSGVR_L
 WHERE NBW_MESG_APLY_DT = (
   SELECT MAX(NBW_MESG_APLY_DT)
     FROM CPBBO_MSGVR_L
    WHERE NBW_MESG_TYCD = :tx_tp_cd
      AND NBW_MESG_VER_NO > :tx_ver_no
 )
    OR NBW_MESG_APLY_DT = (
   SELECT MAX(NBW_MESG_APLY_DT)
     FROM CPBBO_MSGVR_L
    WHERE NBW_MESG_TYCD = :tx_tp_cd
      AND NBW_MESG_VER_NO < :tx_ver_no
 )
   AND NBW_MESG_TYCD = :tx_tp_cd;
```

> ☑ `UNION ALL` 없이도 상·하위 버전의 최신 적용일자를 한 번에 조회하는 방식

## 📌 전문버전 등록/수정 시 적용일자 검증 로직

### 🔸 목적

- 전문버전번호 간 적용일자 정합성 유지
- **이전 버전보다 빠른 적용일자만 허용**
- **이후 버전보다 늦은 적용일자 등록 방지**

---

### 🔹 처리 흐름 요약 (ACSD 기준)

1. `전문버전내역적용일자목록조회` OP 호출
    
    - 입력: `전문버전수정Dto`
    - 출력: `적용일자조회결과Dto[]`
2. 조건문 ① (과거보다 빠름만 허용):
    

```java
if (
  r전문적용일자조회결과Dto.전문버전번호 < i전문버전수정.전문버전번호 &&
  r전문적용일자조회결과Dto.적용일자 >= i전문버전수정.적용일자
) {
  // 적용일자 오류 처리
}
```

3. 조건문 ② (미래보다 느림 불가):

```java
if (
  r전문적용일자조회결과Dto.전문버전번호 > i전문버전수정.전문버전번호 &&
  r전문적용일자조회결과Dto.적용일자 <= i전문버전수정.적용일자
) {
  // 적용일자 오류 처리
}
```
