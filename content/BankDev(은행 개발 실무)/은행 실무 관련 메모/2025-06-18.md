## 📌 paging 이란?

- **의미**: 화면에 데이터를 뿌릴 때 한 번에 몇 개를 보여줄지 제어하는 기능
- 예: 한 화면에 10건만 보여주고, 다음 페이지로 넘김

---

## 📌 OP 명명 규칙

- OP 이름에 **"목록"** 이 포함되지 않으면, 파라미터에 **다중성(*) 부여 시 오류 발생**
- 따라서, **목록 조회**라면 반드시 `…목록조회`처럼 명시적으로 작성할 것

## 📌 용어 등록 및 DTO 반영 절차

### 🔹 주요 용어 (전문버전 비교용)

|용어명|설명|
|---|---|
|`신한은금융망전문버전번호상위_S16`|상위 버전 번호 (S16)|
|`신한은금융망전문버전번호하위_S16`|하위 버전 번호 (S16)|
|`신한은금융망전문적용일자상위_S16`|상위 적용일자 (S16)|
|`신한은금융망전문적용일자하위_S8`|하위 적용일자 (S8)|

### 🔹 등록 절차

1. `META > 표준데이터 > 전문용어등록요청` 에서 용어 등록
2. `DevOnMDA > Code > 용어사전리로딩` 실행
3. 해당 용어는 **쿼리 결과와 DTO 필드에 일치시켜야 함**
4. 쿼리 결과 사용 시 → 반드시 `EBI` 내 DTO에 추가할 것

## 📌 DTO/OP 연결 구조 설명

### 🔸 `<<i, ebi>>` 블럭

- `PBI` 단말의 입력 데이터를 `EBI`의 OP로 전달할 때 사용
- 즉, **단말 ↔ 백엔드 연계 지점**
- OP에서 선언된 **입력 DTO와 매핑**되어야 하며, 필드명이 정확히 맞아야 함

### 🔸 `<<c, dao>>` 블럭

- `EBI`의 OP 내부에서 실제 쿼리(XML)를 실행하는 연결 블럭
- OP에서 지정한 `@SqlId` 가 DAO XML 내부의 `<statement name="…">` 와 연결됨
- 이 블럭 없이는 쿼리 실행 불가

### 🔄 흐름 정리

```plaintext
[PBI 화면 입력 DTO]
    ↓
<<i, ebi>>  →  EBI 입력 DTO 세팅
    ↓
<<c, dao>>  →  DAO XML 쿼리 실행
    ↓
[EBI 출력 DTO 반환]
```

## 📌 `<<op, Interaction Block>>` 설명

### 🔹 정의

- 여러 ACSD에서 공통으로 반복되는 로직을 묶어서 재사용하는 블럭
- `<<op, Interaction Block>>`는 **하나의 논리 흐름 단위**로 재사용 가능

### 🔹 적용 예: 전문버전 등록 vs 수정 시 적용일자 검증

- 입력 DTO만 다르고, 나머지 로직은 동일
- → 공통 블럭으로 추출하고 변수만 재매핑하여 재사용

#### 🔹 변수 매핑 예시

```java
String [s신한은금융망전문버전번호] = [iISO20022전문버전등록].[신한은금융망전문버전번호];
String [s신한은금융망전문적용일자] = [iISO20022전문버전등록].[신한은금융망전문적용일자];
```

수정 ACSD에서는 `iISO20022전문버전수정`으로 치환

### 🔸 검증 조건 (논리코드 if문)

```java
// 하위 버전과 비교
if (
  [r전문버전내역적용일자조회].[신한은금융망전문버전번호하위_S16] < [s신한은금융망전문버전번호] &&
  [r전문버전내역적용일자조회].[신한은금융망전문적용일자하위_S8] >= [s신한은금융망전문적용일자]
) {
  code = "9999";
  params = "적용일자 오류";
  return;
}

// 상위 버전과 비교
if (
  [r전문버전내역적용일자조회].[신한은금융망전문버전번호상위_S16] > [s신한은금융망전문버전번호] &&
  [r전문버전내역적용일자조회].[신한은금융망전문적용일자상위_S8] <= [s신한은금융망전문적용일자]
) {
  code = "9999";
  params = "적용일자 오류";
  return;
}
```

## 📌 적용일자 검증을 위한 최종 쿼리 (단일 행 조회 + 병합)

```sql
SELECT
    MAX(A) AS NBW_MESG_VER_NO_UPRN_S16,    -- 상위 버전번호
    MAX(B) AS NBW_MESG_APLY_DT_UPRN_S16,   -- 상위 적용일자
    MAX(C) AS NBW_MESG_VER_NO_LWRN_S16,    -- 하위 버전번호
    MAX(D) AS NBW_MESG_APLY_DT_LWRN_S8     -- 하위 적용일자
FROM (
    SELECT
        NBW_MESG_VER_NO AS A,
        NBW_MESG_APLY_DT AS B,
        '' AS C,
        '' AS D
    FROM (
        SELECT NBW_MESG_VER_NO, NBW_MESG_APLY_DT
        FROM CPBBO_MSGVR_L
        WHERE NBW_MESG_TYCD = ${nbw_mesg_tycd}
          AND NBW_MESG_VER_NO > ${nbw_mesg_ver_no}
        ORDER BY NBW_MESG_VER_NO ASC
    )
    WHERE ROWNUM = 1

    UNION ALL

    SELECT
        '' AS A,
        '' AS B,
        NBW_MESG_VER_NO AS C,
        NBW_MESG_APLY_DT AS D
    FROM (
        SELECT NBW_MESG_VER_NO, NBW_MESG_APLY_DT
        FROM CPBBO_MSGVR_L
        WHERE NBW_MESG_TYCD = ${nbw_mesg_tycd}
          AND NBW_MESG_VER_NO < ${nbw_mesg_ver_no}
        ORDER BY NBW_MESG_VER_NO DESC
    )
    WHERE ROWNUM = 1
)
```

### ✅ 장점

- 상하위 버전 각각 **최신 1건만 조회**
- 루프 없이 단일 쿼리 결과로 검증 가능
- `Interaction Block`과 함께 사용할 때 가장 효율적
