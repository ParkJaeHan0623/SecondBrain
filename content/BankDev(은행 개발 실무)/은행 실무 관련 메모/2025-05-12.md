# ✅ 2025-05-12 NVL 함수 + 전문버전내역 테이블 정리
## 📌 NVL 함수란?
~~~sql
NVL(값1, 값2)
~~~

>`값1`이 `NULL`일 경우, `값2`로 대체하여 반환
  `NULL`로 인해 연산이 불가능한 상황을 방지하기 위해 사용


#### 🔹 예시:

~~~sql
SELECT NVL(전화번호, '없음') FROM 고객; -- → 전화번호가 NULL인 경우 '없음'으로 출력됨
~~~

## 📌 Oracle Sequence 개념

- Oracle에서 자동으로 숫자를 증가시키는 객체
- 일련번호(PK)를 DB가 자동으로 생성하도록 할 수 있음

#### 🔹  예시:

~~~sql
SELECT 시퀀스명.NEXTVAL FROM DUAL; -- → 다음 일련번호를 가져오는 쿼리
~~~
- 보통 `INSERT` 전에 호출하여 DTO에 값 세팅 후 사용

#### ⚠️ **전북은행에서는?**

- 시퀀스 사용 시 DB 권한이 필요
- 요청/등록 절차가 번거로워 실무에서는 `MAX + 1` 방식으로 대체하는 경우도 있음
- 단, **동시성 문제** 발생 가능 → 다중 사용자 환경에서는 비권장

## 📋 전문버전내역 테이블 구조

|컬럼명|설명|
|---|---|
|신한은금융망서비스식별값|연계 서비스 ID (예: `TX_SVC_ID`)|
|신한은금융망전문유형코드|전문의 분류 코드 (예: `TX_TP_CD`)|
|신한은금융망전문적용일자|전문의 적용 시작일 (`YYYYMMDD`)|
|신한은금융망전문버전번호|전문의 버전 번호 (정렬 기준)|
|일련번호|고유 식별자 (PK 또는 정렬 기준)|
|한국은행원장상태코드|전문의 사용 상태 (예: 유효/미사용 등 상태값)|

## 📌 연계 기준 및 실무 활용

- 위 컬럼들을 기준으로 **조회 / 등록 / 수정** 관련 연계 로직 구성

#### 🔹 **예시 사용 방식:**

- **단건 조회**: `전문유형코드 + 버전번호`로 조회

- **목록 조회**: `전문유형코드` 기준 조건 설정

- **등록/수정**: `전문유형코드 + 버전번호` **중복 여부 확인 필수**


#### 🧠 **실무 참고사항**

- `전문버전번호`는 **중복 방지 및 정렬용 키(PK 후보)로 활용됨

- `일련번호`는 정렬 기준 또는 고유 식별자 역할

- `적용일자`는 신규 적용 시점 판단 및 **과거 버전 관리에 필수**
