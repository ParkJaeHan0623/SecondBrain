# 📅 2025-05-22 전문버전 단건 조회 SQL 정리

---

## 📌 단건 조회 목적

- 특정 전문유형코드에 대해 **오늘 날짜를 기준으로 유효한 최신 전문버전**을 조회하기 위함
- 조회 결과로 **전문정의식별값**과 **서비스식별값**을 반환

---

## 📄 SQL 예시 ① (서브쿼리 사용)

~~~ sql
SELECT 
  신한은금융망전문유형코드 || 전문버전번호 AS 신한은금융망정의식별값,
  신한은금융망서비스식별값
FROM 전문버전내역
WHERE 전문유형코드 = :전문유형코드
  AND 전문적용일자 = (
    SELECT MAX(전문적용일자)
    FROM 전문버전내역
    WHERE 전문유형코드 = :전문유형코드
      AND 전문적용일자 <= TO_CHAR(SYSDATE, 'YYYYMMDD')
);
~~~

- `MAX(전문적용일자)`를 사용하여 **오늘 기준 가장 최신 적용일자**를 추출
- 해당 일자에 해당하는 단일 레코드를 조회

## 📄 SQL 예시 ② (정렬 + FETCH 방식)

~~~sql
SELECT
    신한은금융망전문유형코드 || 전문버전번호 AS 신한은금융망정의식별값,
    신한은금융망서비스식별값
FROM
    전문버전내역
WHERE
    전문유형코드 = :전문유형코드
    AND 전문적용일자 <= TO_CHAR(SYSDATE, 'YYYYMMDD')
ORDER BY
    전문적용일자 DESC,
    전문버전번호 DESC
FETCH FIRST 1 ROW ONLY;
~~~

- `ORDER BY`로 정렬 후 `FETCH FIRST 1 ROW`로 최신 1건 추출
- 성능과 가독성 면에서 실무에서 자주 사용됨  

---

## ✅ 참고 사항

- **전문정의식별값**: 전문유형코드 + 전문버전번호를 결합한 값

- **전문적용일자**는 `VARCHAR(8)` 이므로 날짜 비교 시 `TO_CHAR(SYSDATE, 'YYYYMMDD')` 사용 필요

- 위 두 SQL은 **같은 목적**을 달성하지만 상황에 따라 성능 및 가독성에서 차이가 있음


## 🧠 실무 팁:

- 정렬 방식(`ORDER BY + FETCH`)은 옵티마이저에 따라 더 빠를 수 있음

- 반면 `MAX()` 서브쿼리는 직관적이고 유지보수에 유리할 수 있음
