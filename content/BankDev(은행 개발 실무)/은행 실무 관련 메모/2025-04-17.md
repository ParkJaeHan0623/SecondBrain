오늘은 **DEVON에서 거래 로그를 보는 방법**을 배웠다.  
단말에서 발생한 요청의 흐름을 추적하고, 로그를 통해 문제를 파악하는 아주 중요한 기능.  
만약 로그가 조회되지 않을 때 조치 방법도 함께 익혔다.

---

# 📅 2025-04-17 DevOn 거래로그 확인 절차

---

## 📌 기본 거래 로그 조회 방법

1. **통합단말에서 트랜잭션 실행**
2. 우측 하단 `녹색 [자세히보기]` 버튼 클릭
3. `GUID` 복사
4. DevOn 접속 →  
    `서비스관리 > 거래로그관리 > 거래로그조회`
5. `GUID` 붙여넣고 조회

→ 성공적으로 요청이 발생했다면, 관련 로그가 출력됨  
→ 이 로그를 통해 어떤 파라미터가 전달되었고, 어떤 응답이 왔는지 확인 가능

---

## 🛠 로그가 조회되지 않는 경우 대처법

> 서비스 자체에 로그가 비활성화되어 있는 경우 로그가 안 찍힐 수 있음

### ▶ 조치 방법

1. DevOn 접속
2. `서비스관리 > 파라미터관리 > 서비스파라미터관리`
3. 해당 **서비스ID** 입력 후 조회
4. 하단 **[로깅정보]** 탭 이동

#### 🔧 설정

| 항목                | 설정값                 |
| ----------------- | ------------------- |
| **시스템 로그레벨**      | 전부 체크               |
| **Trace 로그 출력옵션** | 전부 체크               |
| **Trace 로그레벨**    | `0` (ALL / default) |

---

## 📎 부가 정보

- **GUID**: 거래 1건의 고유 식별자  
    → 이걸 기준으로 로그 전체 추적 가능
    
- **서비스파라미터관리**: 로그뿐만 아니라 트랜잭션의 구현 클래스 및 흐름도 확인 가능
    

---

## 🧠 오늘의 깨달음

- DEVON에서 로그 보는 법은 실무에서 **디버깅의 기본 중 기본**
- 로그가 안 나올 땐 "로그 설정을 의심하라"는 것도 기억해두자
- GUID, 서비스ID, 로깅설정의 3종세트는 문제 추적의 핵심 도구다
