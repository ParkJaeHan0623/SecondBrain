## 🔹 ISO20022 전문버전관리 - 일련번호 추가 이슈

## 📌 부장님 지시사항
- ISO20022 전문버전관리 화면에 **일련번호 컬럼**을 추가하라고 하심
- 이유는 **인덱스를 빨리 타기 위해서**라고 하셨는데, 인덱스 개념이 어려워서 직접 정리해봄

---

## 📌 📋 일련번호(PK)의 필요성

1. **행(Row)을 유일하게 식별하기 위해**
   - 테이블에서 각 데이터를 고유하게 구분할 수 있어야 한다
   - 이를 위해 **Primary Key(PK)**로 일련번호 사용

2. **UPDATE, DELETE 시 성능 개선**
   - WHERE 조건에 일련번호를 넣으면 **단일 행**이 바로 식별됨
   - **인덱스를 빠르게 타는 구조**가 된다

3. **정렬 기준으로 사용**
   - 최신 순으로 정렬할 때 유용함
   - `ORDER BY 일련번호 DESC` 등 사용 가능

---

## 📌 🔍 인덱스(Index)란?

- **테이블의 특정 컬럼에 대한 검색 성능을 향상시키는 구조**
- 마치 책의 "색인"처럼 → 원하는 정보를 빠르게 찾기 위한 포인터 역할

### 📂 인덱스의 내부 구조

- **B-Tree(Balanced Tree)** 구조
  - 트리 형태로 **정렬된 상태**로 저장됨
  - 검색, 정렬, 범위 조회가 빠름

### ⚙️ 언제 인덱스를 타는가?

- Oracle의 **옵티마이저(Optimizer)**가 실행 계획 수립 시 판단
- 대표적인 인덱스 사용 케이스:
  - WHERE 절에 **인덱스가 걸린 컬럼**이 단독으로 사용될 때
  - 데이터 건수가 많고 조건이 잘 분리될 때
  - JOIN, ORDER BY, GROUP BY 시 성능 향상

---

## ✅ 실무 예시

- `일련번호`를 PK로 지정하고 인덱스를 걸면,
```sql
SELECT * FROM 전문버전내역
 WHERE 일련번호 = '1001';
```

> 위와 같은 쿼리는 인덱스를 타고 바로 해당 Row로 Jump


## 🧠 정리
일련번호는 단순 번호가 아니라 DB 성능을 높이는 핵심 키 중 하나

특히 수정/삭제/정렬이 많은 테이블에서는 필수 컬럼

인덱스와 PK는 성능 최적화의 핵심 요소
