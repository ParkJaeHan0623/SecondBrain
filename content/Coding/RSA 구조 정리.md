RSA 구조 및 실무 컴포넌트 정리

> 이 문서는 RSA 실무 구조와 각 컴포넌트 개념을 정리한 문서입니다. Obsidian에서 [[Second Brain]] 스타일로 연결해 정리할 수 있도록 구성했습니다.




---

1. [[RSA]] 구조 개요

RSA는 연계 전문 처리를 위한 모델링 기반 프레임워크입니다. DEVON, 단말, 계정계 등과 연동되며, 전문 생성/송신/수신/매핑을 주로 처리합니다.

핵심 컴포넌트

[[PBI]]: 연계 처리의 핵심 논리를 구현

[[EBI]]: 수신 전문 처리 로직 담당

[[PBC]]: PBI의 진입 클래스 (외부 호출 진입점)

[[ACSD]]: 시퀀스 다이어그램 (업무 흐름 정의)

[[AMCD]]: 업무유형 기반 컴포넌트 정의

[[논리코드]]: ACSD 각 단계의 실제 코드 로직

[[DTO]], [[DtoDm]], [[DtoPk]], [[DtoTb]]: 데이터 구조 정의

[[OP]]: 전문 송수신 포맷 정의



---

2. [[PBI]], [[EBI]], [[PBC]] 구조

컴포넌트	설명

<<i, pbi>>	연계 업무 핵심 로직 (예: 조회, 등록, 수정)
<<c, pbc>>	PBI를 호출하는 진입 클래스
<<i, ebi>>	수신 전문 처리 로직 (외부에서 RSA로 들어오는 전문을 받는 쪽)
<<c, ebc>>	수신 처리를 위한 외부 진입점
<<c, dao>>	DAO 클래스 (DB 쿼리 실행용)



---

3. [[ACSD]]와 [[AMCD]]

ACSD

업무 흐름을 시각적으로 모델링한 시퀀스 다이어그램

각 단계(1.1, 1.2...)마다 논리코드가 연결됨

MDA 코드 생성 시 .java 파일로 변환됨


AMCD

업무 유형을 등록/정의하는 상위 컴포넌트

각 AMCD 안에 여러 PBI가 들어갈 수 있음

4. [[논리코드]] 문법 및 구조

구조

[iDto명].[필드명] = [rDto명].[필드명];

접두어 의미:

i: input (입력 DTO)

r: result (응답 DTO)

p: process (중간 처리값)



기능

DTO 간 매핑

조건 분기 (if)

유효성 검사

로그 출력


예시
~~~

if ([i고객조회].[고객ID] != null) {
  [p고객].[조회일자] = Sysdate();
  [r고객조회].[결과코드] = "0000";
}

~~~

5. [[DTO]], [[DtoDm]], [[DtoPk]], [[DtoTb]]

타입	설명

<<dto>>	일반 DTO 객체
DtoDm	요청용 DTO (단말 → RSA)
DtoTb	DB 매핑용 테이블 DTO
DtoPk	테이블의 기본키 전용 DTO


사용 위치 예시

단말 요청값 → DtoDm

결과 응답값 → 결과Dto

DB 접근시 → DtoTb, DtoPk

7. 자주 받았던 질문 요약

Q. 자바코드는 논리코드 해석용인가요?

→ ✅ 맞습니다. .java는 논리코드를 Java 코드로 본 모습일 뿐, 수정용이 아닙니다.

Q. JBNgels는 초기화되나요?

→ ❌ 초기화 기능은 없지만, 모델 기반으로 언제든 삭제 후 재생성 가능합니다.

Q. ACSD 여러 개가 같은 .java 파일로 들어갈 수 있나요?

→ ✅ 가능하지만, 같은 Implementation Class로 지정돼 있을 때만 그렇습니다. 기본은 1 ACSD = 1 Java.

Q. ECAMS로 JBNgels 복구되나요?

→ ❌ 불가능. JBNgels는 모델 산출물이므로 형상관리 대상이 아닙니다.

Q. DTO는 기능별로 나눠야 하나요?

→ ✅ 조회/등록/수정은 각자 다른 DtoDm, 결과Dto를 사용하는 게 실무 표준입니다.
