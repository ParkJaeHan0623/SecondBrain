오늘은 MCI와 단말 ↔ 계정계 간의 연계 흐름을 처음 배웠다.  
ServiceID(트랜잭션)를 중심으로 **데이터 구조와 흐름을 동기화하는 개념**인데, 처음 접했을 땐 꽤 헷갈렸다.

# 📅 2025-04-21 MCI 연동 구조 및 화면 개발 개념 정리

---

## 📌 MCI란?

- **MCI (Message Control Interface)**  
    → **단말(iDevTool)과 계정계(RSA)** 사이의 인터페이스 연결을 정의한 구조
- **ServiceID** 기준으로 **Input / Output** 구조를 MCI에서 정의하고,  
    동일한 구조를 **RSA (계정계)** 와 **화면 (단말)** 이 공유함

---

## 📌 구조 개념 요약

| 구성요소          | 역할 / 설명                                         |
| ------------- | ----------------------------------------------- |
| **MCI**       | 인터페이스 설계: 트랜 Input/Output 정의, 인덱스 순서 세팅         |
| **RSA**       | 계정계 개발 시스템 (전문 개발, 연계 로직 구현)                    |
| **iDev@Tool** | 단말 화면 개발 툴 (단말 화면 정의, 그리드, 버튼, 스크립트 구현)         |
| **DevON**     | 서비스관리, 거래로그, 파라미터, 서비스ID 검색 등 **통합 서비스 플랫폼** 역할 |

---

## 📌 실제 흐름

1. **MCI에서 트랜(ServiceID) 정의**
    - Input/Output 항목 등록
    - 순서대로 인덱스 세팅
    
2. **RSA에서 같은 트랜에 맞춰 전문 개발**
    - 전문OP 생성
    - ACSD 로직 개발
    - DTO, DAO 연계
    
3. **iDev@Tool에서 MCI에서 공유된 트랜 등록**
    - 트랜 가져오기
    - 그리드, 조회/전송 버튼, 거래구분 바인딩
    - 스크립트(OnClick, OnEndTran 등) 작성

---

## 🧠 메모 포인트

- **MCI는 단순 중계가 아님**  
    → 데이터의 구조와 흐름을 맞추는 핵심 인터페이스 정의 도구
    
- **RSA = 계정계 (전문 처리) / iDev = 단말화면 (사용자 UI)**  
    → 둘이 정확하게 Input/Output을 맞춰야 함
    
- **DevON**은 중간에서 서비스를 묶고, **구현 경로를 추적하고 로그를 관리**하는 역할을 함
