## ✅ RSA 시퀀스 다이어그램 분석 & 구조 학습

---

### 1. 거래코드관리 ACSD 시퀀스 해석

- 1.1 목록조회값 세팅
    
- 1.2 거래코드목록조회 (→ DAO 호출)
    
- 1.3 건수조회
    
- 1.4 출력값 세팅
    
- 1.5 업무로그 등록  
    → 각 단계는 논리코드와 연결되며, 화살표를 더블클릭하면 내부 로직 확인 가능
    

---

### 2. 논리코드 기본 문법 학습 (`i`, `p`, `r`)

java

복사편집

`[i입력DTO].[필드명] = [p처리DTO].[필드명]; [r응답DTO].[필드명] = "값";`

|접두어|의미|
|---|---|
|`i`|Input DTO|
|`p`|Process (중간 처리용)|
|`r`|Result (응답 DTO)|

---

### 3. 논리코드에서 `.필드`는 어디서 오는 건가요?

- `.필드명`은 DTO 안에 선언된 `<<attr>>` 이름과 1:1 대응
    
- 논리코드에서 쓰이는 필드는 반드시 DTO 내부 필드로 정의돼 있어야 함
    

---

### 4. `OP`와 `DTO`는 어떻게 연결되나요?

- OP: 외부 연계 전문 포맷 정의
    
- DTO: 내부 데이터 객체
    
- OP ↔ DTO는 Mapper에서 매핑 정의 (Inbound/Outbound Mapper)
    

---

### 5. `[i거래코드조회]`는 무엇인가요?

- 논리코드에서 사용하는 **입력 DTO 인스턴스 이름**
    
- `<<i, pbi>>`의 `<<OP>> 거래코드조회`와 연결되며,  
    OP ↔ DTO 간 매핑을 통해 데이터가 전달됨
    

---

### 6. ACSD에서 논리코드가 자동 생성되나요?

- ❌ 아니요. 화살표만 그리면 “호출 흐름”만 만들어짐
    
- 실제 내부 로직은 **화살표 더블클릭 후 논리코드 영역에 수동 작성**해야 함
    

---

### 7. `.java` 파일은 논리코드가 어떻게 해석되는지 확인용인가요?

- ✅ 맞음
    
- MDA로 생성된 `.java` 파일은 RSA 내부 논리코드가 실제 Java로 어떻게 변환되는지를 보여주는 참고용
    
- 수정하면 다시 MDA 생성 시 덮어쓰기 되므로 직접 수정은 ❌
    

---

### 8. 같은 CORA에 있는 ACSD인데 왜 다른 `.java`로 생성돼요?

- 각 ACSD마다 `Implementation Class`가 다르게 설정되어 있을 경우 각각 다른 `.java`로 생성됨
    
- 같은 클래스로 묶고 싶다면 ACSD 속성에서 같은 클래스명으로 지정해야 함
    

---

### 9. JBNgels는 ECAMS로 초기화되지 않던데 왜 그래요?

- JBNgels는 RSA 모델 기반으로 생성된 산출물 저장소 (실행용 코드 파일)
    
- ECAMS는 `.emx`, `.dto`, `.op` 등 **모델 파일만 관리**
    
- `.java`, `.class`는 ECAMS 복원 대상이 아니므로 수동 삭제 + 재생성 필요
    

---

### 10. 같은 자바 파일에 코드가 덮어씌워졌어요. 왜 그러죠?

- 여러 ACSD가 같은 `Implementation Class`로 설정돼 있을 경우  
    → MDA 생성 시 `.java` 파일이 덮어써짐
    
- 해결 방법: 각 ACSD마다 클래스를 분리하거나, MDA 생성 시 클래스를 명시적으로 다르게 설정
